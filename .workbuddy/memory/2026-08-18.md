## DM 问答：低相似度问题沉淀 + 真人解答 + 引导问题

需求：`/api/v1/dm-guide/ask` 相似度过低时答案无意义，需把问题存库；提供真人解答接口；用户提过的问题按剧本维度取前三条作为引导问题。

实现（全部完成，51 tests 通过）：
- 新增 `sql/dm_questions.sql`：`script_dm_questions` 表（script_code 聚合维度、question_hash 去重、ask_count 原子计数、status: pending/answered/dismissed、answer/answered_by/answered_at），含 `record_dm_question` RPC（insert on conflict 原子 +1）与 RLS。**需在 Supabase SQL Editor 手动执行后功能才可用**（未执行时落库 best-effort 失败只记日志，不影响 ask 主链路）。
- `config.py`：`dm_ask_meaningful_similarity=0.4`（有意义阈值，必须高于 dm_search_min_similarity=0.25）、`dm_guide_questions_limit=3`。
- `dm_service.ask()`：检索后取 qa/chunk 最高原始相似度（不带 boost），低于阈值 → best-effort 落库 + 响应置 `needHumanAnswer=true`、`bestSimilarity`；落库异常吞掉只记日志。ask() 新增 `user_id` 参数（记录提问者）。
- `dm_store.py`：record_question(走RPC)/get_question/list_questions(带 Content-Range 总数)/answer_question/list_guide_questions(answered 优先 + ask_count 倒序)。
- 新接口（ask_router，前缀 /dm-guide）：`GET /questions`（登录，code/title + status/limit/offset）、`POST /questions/{id}/answer`（登录，answered 可改答案，dismissed 返回 409）、`GET /guide-questions`（公开，code/title 二选一，默认前 3 条）。
- 新增 `tests/test_dm_questions.py`（7 个用例）。

注意：项目 .venv 原本没装 pytest，本次已 pip install pytest 进 .venv。
待办（可选）：真人答案回灌 script_dm_qa 向量库（让后续 ask 直接命中真人答案）未做，是后续增强方向。

## 提问库头像：快照+MQ 方案已回退为「读取时批量关联」（同日追加）

需求：解答记录要能看到解答者头像。先实现了「快照列 + Celery 同步」，经讨论认定为过度设计（数据量小、头像低频变更、profiles 同库可关联），用户拍板**简化**。

最终方案（当前线上代码）：
- 提问记录只存 created_by / answered_by（user id），不冗余昵称/头像。
- `dm_store.get_profiles(user_ids)`：`id=in.(...)` 批量查 profiles，一次覆盖整页。
- `dm_service._attach_profiles()`：list_questions / answer_question / guide_questions 读取时合并（纯函数 `_merge_profiles` 可单测）；profiles 查询失败只记日志按无资料返回。
- QuestionRecord 的 6 个展示字段（createdByNickname/createdByAvatarUrl/createdByAvatarColor/answeredBy*）**对外契约不变**，只是改为读取时填充，前端无感。
- `sql/dm_questions.sql` 用幂等清理语句收敛旧库（drop column if exists × 6、drop 旧签名 record_dm_question 重载、drop sync_dm_question_user）——**若之前执行过快照版 SQL，需在 Supabase 重跑一次该文件**。
- 已删除：`app/tasks/profile_sync.py`、celery include/route、auth.py 的 `_fire_profile_sync` 钩子。
- 测试 54 passed。

教训沉淀：给「评论/记录关联用户资料」类需求做设计时，先算数据量级与变更频率——同库小数据量默认走读取时批量关联，只有跨服务边界 / 读放大扛不住 / 需要历史快照语义时才上冗余+事件同步。
