## Redis/worker 未启动导致 DM pipeline 卡死排查与恢复

**症状**：剧本解析在切分为 N 个分片后停止，job 卡在 `extracting` 状态。

**根因**：`.env.local` 设置 `CELERY_EAGER=false`（走真实异步链路），但本机未启动 Redis 和 Celery worker。`prepare_document` 通过 `dispatch_pipeline` → `apply_async` 把 chord 任务派发到 Redis broker，但无 worker 消费，pipeline 停在分片阶段。

**影响范围**：2 个 job 卡死：
- `1a118be8` 猫岛谋杀循环：卡在 extracting（0/5 shards）
- `1c326ff9` 木夕僧之兮：卡在 embedding（9/33 chunks）

**修复步骤**：
1. 启动 Redis：`Start-Process "C:\Program Files\Redis\redis-server.exe" -ArgumentList "--port","6379"`
2. 启动 Celery worker：`.venv/Scripts/python.exe run_worker.py`（threads 池，concurrency=6）
3. 标记旧 job 为 cancelled，创建新 job 并调用 `dispatch_pipeline(force=True)` 重新派发
4. 确认 pipeline 推进：猫岛 → generating_qa（128 块），木夕 → embedding（6/33 块）

**教训**：本地开发需确保 Redis + worker 在后端启动前/同时运行。`.env.local` 的 `CELERY_EAGER=false` 要求 Redis 可达。
