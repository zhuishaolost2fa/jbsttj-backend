# 2026-08-12

## DM 手册 RAG：问答对生成增强 + bug 修复

用户诉求：导入同一剧本不再处理（幂等），希望重新走问答生成流程、补充遗漏信息、按 DM 文档预判用户问题生成尽可能多问答。

### 改动
- `app/services/llm.py`
  - 重写 `_QA_SYSTEM_PROMPT`：强化「预判主持人现场会问的问题」+ 从多角度（规则/线索/角色/时间线/主持技巧/常见玩家疑问）尽可能多生成；保留不编造、无指代词、分类枚举等硬规则。
  - `build_qa_user_prompt` 措辞从「最多 N 条」改为「尽可能多」。
  - `generate_qa` 单批 `max_tokens` 4096 → 8192（避免多问答对被截断）。
- `app/core/config.py` + `.env` + `.env.example`：`dm_qa_per_chunk` 默认 3 → 5。
- `app/services/dm_store.py`：`insert_qa` 入库前按 `question_hash` **同批次去重**，避免 PostgREST 单条 `ON CONFLICT DO UPDATE` 因同批重复问句报 500（code 21000 cannot affect row a second time）。该 bug 在「每片段多生成」后被触发。
- `app/services/dm_service.py`：`maybe_trigger` 增加退化索引（0 块或 0 问答）自动以 `force` 补跑，修复「导入后不再处理」卡死态。

### 验证（真实跑通，EAGER 同步模式，无需 broker/redis）
- 离线校验：新提示词措辞 + 解析器兼容「单片段多条多角度」输出。
- 真实 force 重跑 `病娇男孩的精分日记`（code `dm-bingjiao-nanhai`，doc `90e692da-...`）：
  - 修复前：22 块 / 45 问答，且曾因 QA 批内重复问句 500 整轮失败。
  - 修复后：**22 块 / 86 问答**，分类覆盖健康（角色26% 主持技巧24% 线索19% 时间线19% 规则12%）。
- 环境：`.env` 已配 `CELERY_EAGER=true`，`dedup.build_backend` 在 Redis 不可用时自动降级进程内后端，故单机可同步跑通整条流水线。

### 复跑命令（同剧本重新生成问答）
`python scripts/drive_dm_ingest.py --force`（默认 PDF 见脚本 DEFAULT_PDF；也可 `--pdf 路径`）。
API 侧：`POST /api/v1/scripts/{id_or_code}/dm-guide/ingest` 带 `{"force": true}`。
