用户诉求：导入同一剧本不再处理（幂等），希望重新走问答生成流程、补充遗漏信息、按 DM 文档预判用户问题生成尽可能多问答。

- `app/services/llm.py`

用户诉求：调用 `POST /api/v1/scripts` 时若命中唯一约束 `uq_scripts_code`（code 冲突），应是补充/更新操作，而不是新增失败。

### 改动
- `app/services/script_service.py`
  - 原 `_create_new` 改名为 `_create_or_supplement`，新增两层兜底：
    1. 主动 `repo.get_by_code(code)` 命中即按 code 补充更新（合并语义）；
    2. `repo.create` 抛出 23505 唯一约束错误时，按 code 兜底更新（含 `include_deleted=True` 复活被软删的重复行）。
  - 新增 `_merge_upsert`：身份字段（id/code/created_by/created_at/deleted_at）不动；标量以提交为准；数组（aliases/playstyles/themes/tags）取并集；`extra` 按 key 深合并。
  - 新增模块级 `_is_unique_violation(exc, constraint)`：按约束名精确判定（不是只看 23505，避免误判其它表唯一冲突）。
- `app/services/repository.py`：新增 `ScriptRepository.update_by_code(code, data, *, include_deleted=False)`。
- `app/api/v1/scripts.py`：`POST /scripts` 文档补充「code 冲突即补充」说明。
- 新增测试 `tests/test_script_code_conflict.py`（5 例，纯 fake repo，无需真实库）。

## 禁用阿里云 OCR（关闭所有触发入口）

### 背景
`OCR_ENGINE` 默认 `aliyun`，生产环境扫描件 PDF 会走阿里云 `RecognizeAllText` 付费识别；本地引擎（rapid/paddle/tesseract）虽已实现但依赖被注释、未安装。

### 改动（三层拦截，确保任何路径都触不到阿里云 API）
- `app/core/config.py`：`ocr_engine` 默认值 `aliyun` → `rapid`；`OCR_ENGINE` 校验白名单移除 `aliyun`（设 aliyun 启动即 `ValueError` 失败）；更新注释。
- `app/services/ocr.py`
  - `ocr_image`：`engine=="aliyun"` 直接抛 `OcrUnavailable`，绝不调用 `_ocr_image_aliyun`（已变死代码保留）；默认引擎 `rapid`。
  - `get_ocr_client`：改为直接抛 `OcrUnavailable`，不再构建阿里云付费客户端。
  - 更新模块 docstring 与函数 docstring，标注阿里云已禁用。
- `app/tasks/dm_ingest.py`：生产 OCR 兜底分支移除 `get_ocr_client` 构建逻辑，`client` 恒为 `None`，引擎默认 `rapid`。

### 影响
扫描件 PDF 不再产生任何阿里云对外请求；本地引擎未安装时 OCR 优雅跳过（扫描页拿不到文字层）。`scripts/smoke_dm_ocr.py` 是阿里云 OCR 的 QA 脚本，现已失效（依赖阿里云桩客户端），保留但不再适用。

## 修复：DM 手册重传卡在 parsed（0 块入库）—— Redis 去重指纹残留

- 现象：山鬼母（shan-gui-mu）重传同一份 docx 后，job 显示 completed 但 0 块/0 QA，前端停在 parsed。
- 根因：force 重跑只 `purge_document` 清数据库；Redis 去重指纹命名空间 `dm:dedup:{document_id}` TTL 7 天仍存活。同一文件 content_hash 相同 → upsert 复用同一 document → 同命名空间 → 全部 chunk 被判 exact 重复（dropped=23, kept=0）。首轮 22 块/49 QA 已被 purge，不可恢复。
- 修复：`app/tasks/dm_ingest.py` 的 `chunk_and_dedup` 在 build_backend 后先 `backend.clear()`（含异常兜底），同时覆盖 T2 重试误杀场景。
- 回归测试：`tests/test_dedup_namespace_reset.py`（共享后端模拟 Redis，两轮跑验证 + clear 失败不中断）；全套 34 个测试通过。
- 部署：需 commit+push 到 GitHub，Railway 自动重建后用户重传即可。
- 旁证：shan-gui-mu-2 文档其实有 22 块/54 QA 在库（job 行停在 embedding 属显示问题，可问答）；dm-haomen46-shanguimu 测试剧本数据完整（22/56）。
