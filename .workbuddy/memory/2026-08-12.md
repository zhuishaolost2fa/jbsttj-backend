## DM 手册 ask 接口改造（向量检索问答）
- 新增扁平接口 `POST /api/v1/dm-guide/ask`：请求体传 `code`（剧本编码/UUID，界定检索范围）+ `询问`/`question`（自然语言问题），不再依赖 URL 路径参数。
- 后端逻辑复用 `DMGuideService.ask`：用 `code` 解析剧本 → `询问` 向量化 → 在该剧本手册内做向量检索 → LLM 合成带引用出处的答案。检索范围被 `code` 严格限定，不跨剧本。
- `AskRequest` 新增可选字段 `code`，并为 `question` 增加中文别名 `询问`（populate_by_name 已开启，两者都接受）。
- 旧路径接口 `POST /scripts/{id_or_code}/dm-guide/ask` 保留兼容。
- 涉及文件：`app/schemas/dm_guide.py`、`app/api/v1/dm_guides.py`（新增 `ask_router`，prefix=/dm-guide）、`app/api/v1/router.py`（注册 `dm_guides.ask_router`）、`tests/test_dm_guide_ask_request.py` 增补别名/code 测试（已通过）。
- 前端交付：`docs/dm-guide-ask-frontend.md`（对接方案）+ `frontend/dm-ask-demo.html`（可运行演示，访问 /demo/dm-ask-demo.html）。
- 设计取舍：`code` 用于界定检索范围（scope filter），`询问` 单独向量化；未把 code 文本拼进 embedding，以避免与已入库 chunk/qa 的向量空间错位。若需进一步增强短 query 召回，可后续评估「query 端拼接剧本标题」的开关。

## 剧本重传去重修复（杜绝假续集编码 shan-mu-gui-2）
- 现象：同一本《山母鬼》上传两遍，第二遍生成 `shan-mu-gui-2`。根因不是续集逻辑，而是 `slugify`+`_generate_code` 的防重名自增序号；更深根是 `find_existing(title)` 只做标题精确匹配，两次上传标题略有差异（文件名/副本/扩展名）就没去重，走了新建分支。
- `_generate_code` 的 `-N` 后缀语义 = 防重名自增，不等于「第 N 部」；且 `shan-mu-gui-2` 会与真续集《山母鬼2》的 slugify 结果撞车，无法区分。
- 修复：在 `repository.py` 新增 `normalize_title_key`（去扩展名/首尾空白/系统复制噪音「副本」「（1）」，保留用户有意序号「山母鬼2」「山母鬼 第二部」）；`find_existing` 用归一化钥匙同时匹配 `title` 与 `aliases`；创建/合并时把归一化钥匙写入 `aliases`，使重传稳定合并回原行。
- 新增 `tests/test_title_dedup.py` 锁住行为（沙箱 venv 缺 httpx 跑不了，需在已装依赖环境运行）。
- 待办：用户库里已有的 `shan-mu-gui-2` 假重复行建议软删清理；真续集仍按「不同标题→不同 slug」区分，必要时加 `series_code`/`episode`/`prequel_code` 显式关联（本期未做）。
