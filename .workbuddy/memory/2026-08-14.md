# 2026-08-14

## Bug 修复：DM 手册删除旧文件/换文件重传后，解析状态文件名卡在旧文件

现象：用户先传山鬼母 PDF，删除后传 docs，但 `import-status` / `dm-guide` 的解析状态仍显示 PDF。

根因（已确认，live DB 脚本 2b197314）：
1. `DMGuideService.trigger_ingest` 的「已有 active 任务」守卫（`find_active_job`）在文件已变更时不感知，
   直接复用旧任务 → 新文件被忽略，状态停在旧（PDF）任务上。
2. `get_status` 取「最新激活文档 / 最新任务」而非「当前 `extra.dmGuide.objectKey` 对应的文件」，
   旧文件文档因 `created_at` 更新被当成「最新」。

修复（app/services/dm_service.py、app/services/dm_store.py）：
- `trigger_ingest`：当 active 任务的 object_key 与当前文件不一致时，取消旧任务（cancelled）并按新文件重新派发；
  派发前调用新增的 `deactivate_documents_not_matching` 把不匹配当前文件的其他激活文档下线。
- `get_status`：把 latest_doc / latest_job 锚定到 `ref.object_key`（当前关联文件），找不到时再回退最新。
- `DMStore.latest_job` 新增 `object_key` 过滤参数；新增 `deactivate_documents_not_matching`。

同时清理了受影响脚本 2b197314 的残留状态：取消仍在跑的 PDF 任务（extracting）、下线 PDF 文档，
现状态文件已显示 docx。如需对 docs 重新建索引，让用户重新上传/触发 ingest 即可（修复后行为正确）。
