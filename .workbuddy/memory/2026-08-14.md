## Bug 修复：DM 手册删除旧文件/换文件重传后，解析状态文件名卡在旧文件

现象：用户先传山鬼母 PDF，删除后传 docs，但 `import-status` / `dm-guide` 的解析状态仍显示 PDF。

根因（已确认，live DB 脚本 2b197314）：
1. `DMGuideService.trigger_ingest` 的「已有 active 任务」守卫（`find_active_job`）在文件已变更时不感知，
   直接复用旧任务 → 新文件被忽略，状态停在旧（PDF）任务上。
2. `get_status` 取「最新激活文档 / 最新任务」而非「当前 `extra.dmGuide.objectKey` 对应的文件」，
   旧文件文档因 `created_at` 更新被当成「最新」。

修复（app/services/dm_service.py、app/services/dm_store.py）：
- `trigger_ingest`：当 active 任务的 object_key 与当前文件不一致时，取消旧任务（cancelled）并按新文件重新派发；
  派发前调用新增的 `deactivate_documents_not_matching` 把不匹配当前文件的其他激活文档下线。
- `get_status`：把 latest_doc / latest_job 锚定到 `ref.object_key`（当前关联文件），找不到时再回退最新。
- `DMStore.latest_job` 新增 `object_key` 过滤参数；新增 `deactivate_documents_not_matching`。

同时清理了受影响脚本 2b197314 的残留状态：取消仍在跑的 PDF 任务（extracting）、下线 PDF 文档，
现状态文件已显示 docx。如需对 docs 重新建索引，让用户重新上传/触发 ingest 即可（修复后行为正确）。

## Bug 修复：DM 解析任务卡在 embedding（embed worker 假死）

现象：7 个 DM 任务永久停在 `embedding`，前端 `import-status` 一直 `parsing`；众念成形（`4313d539`）因 `trigger_ingest` 里 `deactivate_documents_not_matching` 的
`script_code` 被按位置传入（该参数为仅关键字）抛 `TypeError`，被 `maybe_trigger` 静默吞掉，连任务都没建 → 前端永远 `pending`（已先修此参数 bug）。

真正根因（卡 embedding）：`app/tasks/celery_app.py` 把 `dm.finalize` 和 `dm.on_pipeline_error` 路由到 `default` 队列，
但 4 个 Celery worker（supervisord.conf）各自独占 `dm.extract/chunk/qa/embed`，**无人消费 `default`**。
→ chord 的收尾回调 `finalize`（把 job 翻 `completed`）与失败回调 `on_pipeline_error`（翻 `failed`）永远不执行。
流水线跑完 embedding 后，job 永久卡 `embedding`；失败时也永远不翻 `failed`。

修复：`dm.finalize` / `dm.on_pipeline_error` 改路由到 `dm.chunk`（worker_chunk 常驻消费）。验证 `task_routes` 已无 `default` 引用。

补救（已对生产 Supabase 直接执行，非代码）：7 个 embedding 任务中，山鬼母(`cc34a644`) 数据完整直接 finalize；
另 6 个（樱再会霜汐子、雪乡连环杀人事件×2、无相人考古奇案、猫岛谋杀循环等）块 100% 入库、QA 因 `question_hash` 去重略少，
判定索引可用，已用 `finalize.apply`（本地 eager）补跑收尾 → 状态翻 `completed`、可问答。
众念成形(`4313d539`) 用本地 eager 后台跑完整条流水线，会自行 finalize。
注意：本机 `CELERY_EAGER=True`，故 `finalize.apply` / `trigger_ingest` 都本地同步执行，不依赖 worker/broker。

部署提醒：celery_app.py 的改动需 git push → Railway 重新部署才对生产新任务生效；补救是直接改库，已即时生效。
orphan 的 `default` 队列在 broker 上可能还残留旧 finalize 消息（无害，幂等；新任务已不再进 default）。
