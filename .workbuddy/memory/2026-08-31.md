## 剧本删除功能收敛为 sql/script_delete.sql

把散落在三处的删除语义收敛成单一 SQL 文件（Supabase SQL Editor 整段执行，幂等）：

- `purge_dm_document(uuid)` —— 单文档清理（重跑/force 前用），highlights 不删只置 orphaned；
- `purge_script_dm_side_effects(uuid)` —— 剧本级物理清理，先 cancel 未终结 jobs，再按
  highlights→stories→chunks→qa→questions→documents→jobs 从叶子到根删，返回 jsonb 行数报告；
- `preview_script_dm_purge(uuid)` —— 干跑预览；
- `count_file_references(text)` / `count_dm_guide_refs(text, uuid)` —— OSS 秒传场景下的引用计数，
  两者都为 0 才允许物理删对象（SQL 层没有 OSS 凭据，返回 oss_delete_required 交给后端删）；
- `soft_delete_script(uuid, uuid, boolean)` —— 主入口，对应 ScriptService.delete_script；
- `restore_script(uuid, text)` —— 撤销软删，code 冲突返回 code_conflict 而非抛约束错误；
- `hard_delete_script(...)` —— 运维专用，默认先把 script_requests.script_id 置空（外键 NO ACTION）；
- `purge_orphan_dm_data(int)` + `v_dm_orphan_scripts` 视图 —— 巡检兜底，建议挂 pg_cron；
- `check_script_delete_installed()` —— 自检：确认 9 个函数齐全且 purge_dm_document 是 plpgsql 版
  （dm_rag.sql / dm_story.sql 各有一份 language sql 旧实现，事后重跑那两个文件会静默覆盖回来）。

关键约束：
- 执行顺序必须 `scripts.sql → schema.sql → dm_rag.sql → dm_story.sql → dm_questions.sql → script_delete.sql`；
- 全部函数 security definer，仅授权 service_role，anon/authenticated 一律 revoke；
- 清理类函数统一返回 jsonb 报告，便于后端记日志与写测试断言。

## 新增 sql/script_delete_runbook.sql

删单本剧本的操作手册（与 script_delete.sql 分工：后者建函数跑 1 次，前者照着跑每次）。
内容：①按标题/编码定位剧本 → ②preview_script_dm_purge 预览 → ③soft_delete_script
（3-A/3-B/3-C 三种参数组合，附返回示例与 ok=false 三种原因）→ ④校验 → ⑤OSS 对象
（SQL 无凭据，oss_delete_required=true 后走后端 delete_object 或 ossutil rm）→ ⑥restore_script
→ ⑦hard_delete_script → ⑧批量兜底 purge_orphan_dm_data + pg_cron → ⑨curl/PostgREST 示例。

安全约定：所有**改数据**的语句一律放在注释块里、留 `<...>` 占位符，整段选中执行不会误删
（未替换的占位符因 uuid 语法错误直接终止）。可直接执行的只有 ① 的查询语句。
此约定适合所有"操作手册型"SQL 文件，后续照此写。
